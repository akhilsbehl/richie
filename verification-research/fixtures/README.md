# Fixtures

Research copies. When the suite is built, these move to `qa/corpus/`.

## Markdown: real review pairs (`markdown/pairs/`)

Nine original + `-commented.md` pairs copied from `~/.richie/ephemeral/` (file times preserved). Topics are pi and configs tooling; no client content. One file contains the template placeholder `Fractal × Acme · Confidential`, which is not client data.

**Checked on 2026-10-06:** for all 9 pairs, removing every `<<ASB: [rvw_NNN] …>>` marker (and its single leading space, or newline plus fence indent; and the document notes at the top) gives back the original byte for byte. So the originals were not edited after review, and each pair is a valid golden for the current marker format (`[rvw_NNN]` in brackets, `src/store.ts` `marker()`).

**How the suite uses them (replay oracle):**

1. Parse each marker in the commented copy: id, kind and scope (`Comment on block`, `Comment on cell`, `Delete`, …), quoted text, comment.
2. Recover the range: the marker's position in the commented text, minus earlier insertions, is the range end; the quote length gives the start. Check that `source.slice(start, end) === quote`.
3. Post those operations through the HTTP API to a fresh session on the original, then Finish.
4. The new `-commented.md` must equal the stored one exactly.

This turns your real past reviews into regression tests with no hand-written expectations.

**Operation mix in the real data:**

| Marker type | Count |
|---|---|
| Comment on block | 47 |
| Comment on range | 9 |
| Comment on table cell | 6 |
| Delete (range or block) | 5 |
| Document note at start | 3 |
| Replace | **0** |
| Code, Mermaid, math, image, row, column | **0** |

Real usage is mostly block comments. Replace, code-fence, Mermaid, math, media, row and column operations have no real samples. Those need synthetic scenarios (from the manual plans) so they are not left unprotected.
